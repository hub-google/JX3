# 驗證矩陣：什麼才算能用？

**重要：所有偏移均來自外部貼文，不代表現有版本可用。** 模擬測試通過 ≠ 真實遊戲可用，更不代表不會被反作弊系統偵測。

| 層級 | 驗證內容 | 通過條件 | 目前狀態 |
|---|---|---|---|
| L1 靜態檢查 | Python 語法、設定檔存在 | 程式可匯入、無語法錯誤 | 已於 Linux 確認 |
| L2 合成記憶體 | 單位樹、場景道具、BUFF 原始欄位、選取保護 | unittest 所有案例綠燈 | 6 項通過 |
| L3 Windows API | Windows 子行程的 ReadProcessMemory／WriteProcessMemory、模組列舉 | Windows CI 測試全綠（自有測試行程） | 待 CI 結果 |
| L4 真實客戶端 | 真正《劍網 3》遊戲版本的 KWorld、單位表、場景格網解析 | 唯讀報告解析成功且當場遊戲畫面人工對照，至少 3 次；不同場景各一次 | 未驗證 |
| L5 真實資料準確率 | 名稱、玩家/NPC 分類、物資名稱、距離、BUFF 數據 | 逐項與遊戲畫面／官方 API 對照，記錄錯誤筆數 | 未驗證 |
| L6 穩定性 | 進出場景、角色移動、目標消失、版本不同或讀取遭拒 | 不崩潰、不破壞遊戲行程，輸出清楚錯誤 | 未驗證 |
| L7 目標寫入 | 目標句柄與 UI 實際同步、持續穩定、沒有非預期影響 | 僅經授權測試環境取得可重現證據 | 未驗證、預設關閉 |

## 如何驗證（不需要開發者相信你）

1. 先在 Windows 執行 `py -3 -m unittest discover -s tests -v`，確認跨行程自有測試全部通過。
2. 開啟你有權測試的客戶端，在已登入並載入場景的情況執行 `py -3 validate_live_readonly.py`。它只輸出 PID、解析狀態、角色／物資數量和錯誤訊息，不輸出玩家姓名。
3. 若結果失敗，勿改寫遊戲記憶體：先記錄 `error`，確認 Windows 權限、行程名稱、遊戲版本與偏移是否一致。
4. 若狀態是 `parsed_unverified`，**仍不代表正確**：在 GUI 顯示的角色名稱、種類、物資座標和距離，抽樣至少 10 筆與遊戲畫面比對。
5. 分別在有 NPC、玩家與可拾取物的場景重複，至少三次。記錄各功能的正確筆數／總筆數與錯誤。
6. 每次遊戲更新重做 L4、L5；版本沒驗證時不得在 UI 標記「已確認可用」。

## 已知阻礙（原始文章缺漏）

- TargetHandle 宣稱 16B，但已列出欄位共 20B，而且兩槽相距 20B。原型的 20B 只是根據字面推導，並非遊戲實測。
- 紅黑樹 root/head 結構、BUFF 迴圈鏈結的 next 位置、道具鏈 next 位置，均有未經實機驗證的假設。
- BUFF 惰性句柄無解析規則；所以目前不能聲稱讀到 buffID、層數或剩餘時間。
- 單位表可能只包含客戶端已經取得的目標。沒有伺服器資料就不能保證「全圖透視」。
- Windows 自有子行程整合測試無法代表遊戲反作弊產品允許存取。
- 此工具沒有實作反作弊規避。它對遊戲條款或封號風險沒有安全保證。

## 結果分類

- **PASS (simulation)**：只有合成測資通過。
- **PASS (OS adapter)**：證實 Windows 跨行程介面在測試行程可用。
- **PASS (game read-only)**：需真實遊戲逐項對照的實測紀錄。
- **NOT TESTED**：沒有獨立驗證。不能寫成通過。

## Windows 測試員流程（v0.1.2）

1. Windows 10/11 x64、64-bit Python 3.10+。不要將遊戲帳密寫進任何測試報告。
2. 解壓縮 ZIP，先雙擊 `run_diagnostics.bat`。輸出 `diagnostics/jx3-diagnostic-*.json`，內含環境版本、測試結果及錯誤，不輸出角色／道具名稱，也不含記憶體 dump。
3. 雙擊 `start_demo.bat`：應出現合成資料 GUI。截圖時在畫面標明 DEMO，並不是遊戲實測。
4. 如有明確授權且願意承擔反作弊風險，開啟遊戲並待場景完整載入，再雙擊 `run_diagnostics_game_readonly.bat` 做**一次性唯讀診斷**。不用管理員權限先試；若存取被拒，記錄失敗並停止，不修改遊戲保護機制，也不反覆嘗試規避。
5. 若唯讀報告為 `parsed_unverified` 且數量非零，才進行畫面人工對照：三個不同場景、每場景抽樣至少 10 筆角色／NPC 與 10 筆可見物資（若有），記錄「有幾筆對」與距離偏差。不要傳遞其他玩家的真實名稱或完整遊戲畫面中敏感資料。
6. 回傳 `diagnostics/` 內最新 JSON、離線 GUI 是否正常、一個不含帳號敏感資訊的遊戲版本資訊、抽樣比對的筆數與統計，以及程式／遊戲是否異常退出。不要提交帳密、登入憑證、記憶體 dump、反作弊記錄中的識別資訊。
7. 若出現遊戲崩潰、凍結、警告、封號提示、Windows 安全警示或任一反作弊阻擋，**立即停止**，只回報觀察結果，不繼續測試寫入或自動化。

### 常見錯誤對照

| 錯誤現象 | 合理原因（未必唯一） | 處理方式 |
|---|---|---|
| `py` / Python 找不到 | Python 未安裝或 PATH 問題 | 安裝 64-bit Python，重跑離線測試 |
| Windows 整合測試失敗 | API 包裝、位元數、權限或端點保護 | 回報測試錯誤，不繼續碰遊戲 |
| `Game process not found` | EXE 名稱不同、未啟動或未載入 | 記錄 EXE 名稱和遊戲版本；勿猜測驗收成功 |
| `OpenProcess` error 5 | 存取被拒，可能是權限或遊戲保護 | 停止，回報錯誤碼，勿嘗試關閉防護 |
| `ReadProcessMemory` 299/998/487 | 部分複製／無效位址／存取限制，也可能是偏移失效 | 停止，回報錯誤碼和場景，不判定某個偏移必然正確 |
| `indeterminate_empty_units` | 沒解析到任何單位 | 不是通過；先確認是否登入場景及版本吻合 |
| `parsed_unverified` | 解析器有輸出數量 | 仍需人工對照名稱、物件、距離，不能稱已通過 |

### 驗收門檻（提議）

- Windows 子行程測試全綠；未測項不可標為通過。
- 至少 3 個不同場景，每場景至少抽樣 10 個畫面上可見單位（總共 30 個），種類與名稱對照一致率至少 95%。物資若有足量樣本，採相同門檻；不夠樣本應標記待測。
- 以**畫面可見物件**為對照集合，不得把客戶端未收到的伺服器端隱藏物件算成漏抓。
- 觀察 15 分鐘，切換場景／角色移動不應導致工具或遊戲當機；記錄更新延遲與 CPU 使用率，但不把單次測試外推成長期穩定性。
- 對任何與官方反作弊相關的拒絕、封禁或警示，分類為「無法驗證」，不提供規避步驟。
- `--enable-target-write` 及 `start_live_targetwrite.bat` **不屬於本輪測試**，勿執行。
